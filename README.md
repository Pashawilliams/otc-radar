# OTC Radar

Каталог публичных русскоязычных Telegram OTC-чатов: сборщик на Python, сохранение базы в Git и статический сайт на GitHub Pages. На сайте доступны поиск, фильтры, сортировка, количество участников и доступный Telegram показатель «онлайн».

**1500 чатов — цель сбора.** Счётчик показывает только реально проверенные группы. Проект не создаёт фиктивные записи и не считает каналы, ботов и личные аккаунты чатами. Количество доступных подходящих групп зависит от источников, настроек отбора и ограничений Telegram; достижение 1500 не гарантировано.

## Как это работает

1. Сборщик получает кандидатов из исходных источников и публичных ссылок.
2. Проверяет публичную страницу Telegram, тип сообщества, признаки русского языка и OTC-тематику.
3. Нормализует ссылки и устраняет повторы. При работе через Telegram API использует также постоянный ID группы, чтобы учитывать смену username.
4. Сохраняет очередь и накопленные результаты между запусками в `data/state.json` и `web/data/`.
5. GitHub Actions публикует обновлённый сайт через GitHub Pages.

На странице группы указан момент последней проверки. Онлайн — снимок на этот момент; Telegram может его не показывать. В таком случае отображается «нет данных», а не выдуманный ноль. Сумма онлайна разных групп не равна числу уникальных людей: один человек может входить в несколько чатов.

«Русскоязычный» определяется по кириллице в названии/описании, OTC — по тематическим признакам публичного профиля. Это проверяемая эвристика: язык переписки не анализируется. Веб-режим убирает повторы username; смену имени одного чата надёжнее отслеживать через постоянный ID в режиме Telegram API.

Каталог не проверяет надёжность участников, гарантов и торговых предложений. Описания и количество участников берутся из публичных источников.

## Запуск на GitHub

1. Поместите проект в ветку `main` репозитория.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Если политика репозитория запрещает запись для Actions, разрешите её в **Settings → Actions → General → Workflow permissions**. Workflow запрашивает `contents: write` только для сохранения базы; публикация использует отдельные `pages: write` и `id-token: write`.
4. В **Settings → Secrets and variables → Actions → Variables** можно задать `OTC_CATEGORY`: `crypto` (по умолчанию), `gifts` или `all`.
5. В **Actions → Collect OTC chats and publish → Run workflow** запустите первый сбор.
6. Адрес опубликованного сайта появится в deployment **github-pages** и в **Settings → Pages**.

Обычно адрес выглядит как `https://OWNER.github.io/REPOSITORY/`. Для приватных репозиториев доступность Pages и расходы на Actions зависят от тарифа и настроек аккаунта.

Workflow запускается по расписанию **каждые 15 минут**, на 7-й, 22-й, 37-й и 52-й минутах часа, и выполняет ограниченный по времени проход. Страница проверяет доступность новых опубликованных данных каждые 60 секунд. Это разные интервалы: секундный опрос сайта не делает сбор непрерывным.

За проход проверяется до 180 профилей в пределах 300 секунд. Большая база обновляется по очереди, поэтому время проверки конкретного чата может быть старше последнего запуска.

**GitHub Actions не обеспечивает непрерывный процесс и обновления в реальном времени.** Запуски могут задерживаться; каждый запуск имеет ограниченную длительность. Для действительно постоянного сбора нужен постоянно работающий сервер или self-hosted runner. Здесь нет бесконечных самозапусков workflow.

Документация GitHub: [событие schedule и задержки](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [лимиты выполнения](https://docs.github.com/en/actions/reference/limits), [публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Telegram API — необязательный режим

Публичный веб-сбор работает без API-ключей Telegram. Для более полного поиска, проверки постоянных ID и доступной статистики можно подключить пользовательский Telegram API. Добавьте в **Settings → Secrets and variables → Actions → Secrets**:

| Секрет | Значение |
| --- | --- |
| `TELEGRAM_API_ID` | API ID приложения Telegram |
| `TELEGRAM_API_HASH` | API hash приложения |
| `TELEGRAM_SESSION` | StringSession Telethon, созданная локально владельцем аккаунта |

Нужны все три значения. При наличии сессии workflow устанавливает зависимости из `requirements-telegram.txt`. Вход с кодом Telegram выполняется только локально; Actions не запрашивает код входа и не должен получать его через логи. Не добавляйте токены, `.env`, session-файлы и строку сессии в Git. `TELEGRAM_SESSION` даёт доступ к Telegram-аккаунту.

Для создания сессии на своём компьютере: `python -m pip install -r requirements-telegram.txt`, затем `python scripts/create_telegram_session.py`. Полученную строку храните как секрет, не пересылайте в переписку.

Режим API не обходит ограничения доступа и FloodWait. Сборщик не должен автоматически вступать в группы или отправлять сообщения. Без доступа к конкретному закрытому чату собрать его содержимое и статистику нельзя.

GitHub PAT для workflow не нужен: сохранение базы и публикация работают через встроенный `GITHUB_TOKEN` с ограниченными правами.

## Локальный запуск

Требуется Python 3.12+. Для веб-режима зависимости Python не нужны.

```bash
python -m otc_radar collect --budget-seconds 300 --max-profiles 180 --max-searches 4 --target 1500 --category crypto
python -m http.server 8000 --directory web
```

Откройте `http://localhost:8000`. Чтобы показать обе категории, используйте `--category all`. Цель `--target` не является ограничением на размер базы: проверенные результаты продолжают сохраняться.

Проверки:

```bash
python -m unittest discover -s tests
node --check web/app.js
```

## Данные и диагностика

| Файл | Назначение |
| --- | --- |
| `data/state.json` | Очередь кандидатов, состояние обхода и накопленная база |
| `web/data/chats.json` | Проверенные группы для сайта |
| `web/data/status.json` | Состояние последней попытки, время успеха и ошибки |
| `research/` | Исходные материалы поиска и подтверждения кандидатов |

Сборщик сохраняет уже найденные записи при временной ошибке источника. Ошибка сбора отмечается в статусе и не должна превращаться в успешный пустой список. Workflow публикует доступный снимок и сообщает о неуспешном запуске.

Если публикация не появилась, проверьте **Actions**, права Pages и состояние deployment. При конфликте записи в ветку workflow завершится с ошибкой: принудительной перезаписи истории нет.
